Module 01 · Literacy Tier

AI as a System, Not a Search Bar.

Reframe25 minLiteracyWarmth pass

Most people treat AI like Google with better grammar — ask a one-liner, get an answer, close the tab. That's zero compounding. The shift: treat AI like a capable system you design. You write the brief, set the standards, define what good looks like. The model executes. You own the outcome.

The five moves

  • BRIEFWrite the Prompt Brief before the prompt. Persona, 3 constraints, success metric, non-goals. If you can't write those four, you're not ready to prompt.
  • CTXContext is infrastructure. Reuse saved threads, persistent spaces, and pinned sessions the way a dev reuses a repo. One-offs die with the tab.
  • ARCHArchitect first, prompt second. Set the system state — persona, constraints, success metric — before a single line of prompting.
  • RUNTreat output as a draft you commissioned. If it misses, you don't re-ask — you check the brief, same as reviewing work from someone who misread the spec.
  • LOGKeep the artifacts. CSV and HTML exports are checkpoints. Portable context beats re-explaining yourself next session.

Module 02 · Literacy Tier

Define Good
Before You Prompt.

Standards30 minLiteracy

Most AI output is mediocre because the person prompting never defined what "good" looks like. The model can't read your mind. You have to write down the standard before you write the prompt — or you're just hoping the output lands.

Three questions before every prompt

  • WHOWho is this for, and what do they need to do with it? A script hook written for a cold YouTube viewer is different from one written for a subscriber. An exec update for your VP is different from one for your skip-level. Name the reader. Name the action they need to take.
  • WINWhat does success look like, specifically? Not "it's good." What's the word count, the tone, the structure, the one thing it must accomplish? If you can't write the success criteria in one sentence, you're not ready to prompt yet.
  • FAILWhat are the failure signals you'll catch on review? Generic language where your voice should be. A claim that sounds confident but isn't sourced. A hook that could belong to any channel. Name the failure before it happens.
The prompt picks the output. The standard picks the prompt. Work backwards.

This becomes your scoring card in Module 4.

Success check

Module 03 · Application Tier

Prompt Engineering for Real Pipelines.

Chain40 minApplication

A single prompt is a conversation. A chained pipeline is a product. The war story → script → assets → publish flow is five stages, each with one input, one output, one check. That's it — and it runs in under an hour.

The production pipeline, stage by stage

STAGE 1  War story → Research Note
         Prompt: extract conflict, protagonist wound, resolution, ICP hook
         Output: one-page research note with opening line

STAGE 2  Research Note → Script
         Prompt: write 5-act script — hook / context / conflict / resolution / CTA
         Output: full script, ~1,200 words, opens on the wound

STAGE 3  Script → Asset Plan
         Prompt: generate thumbnail copy (ghost words + text overlay) + B-roll list
         Output: thumbnail brief ready for Canva, visual shot list

STAGE 4  Script → Metadata
         Prompt: 5 title variants (2 search-first, 3 emotion-first) + description + tags + chapters
         Output: paste-ready YouTube metadata block

STAGE 5  Script → Shorts Hooks
         Prompt: identify 3 clip moments, each with opening line + retention arc
         Output: 3 Short briefs with hooks + suggested cuts

Why chaining beats single prompts

  • MODModular. Each stage has one input and one output. If your script draft is weak, you fix Stage 2 — you don't restart the war story extraction.
  • GATEHuman gate between stages. You review and approve before the next prompt runs. AI does the generation; you do the judgement.
  • REPLAYReplayable. Save each stage output as a file. Next video starts from a known-good research note format, not a blank chat.
  • 80/20AI does the 80%, you own the 20%. The specific war story, the voice, the ICP nuance — that's yours. AI handles the formatting and the volume.
  • BRIDGENo integration? Build the bridge. YouTube analytics has no Claude connector. Export CSV → sanitize → prompt for insight summary. Duct tape ships.

Module 04 · Application Tier

Discernment: Scoring the AI's Answer.

Evaluate30 minApplication

The hardest skill in this program is not generating — it's judging. Hallucinations come dressed as insight. Confidence is not correctness. This is the muscle that keeps your reputation intact and your audience trusting you.

The discernment moves

  • STANDARDScore against your Module 2 Definition of Good, not vibes. Pull out the card you wrote. Does this output meet the named reader, the success criterion, the failure check? Write the verdict.
  • TRITriangulate. Run the same prompt through a second AI session and compare. If they disagree on a claim, that's a signal — not a tiebreaker, a red flag that needs your research.
  • MISSName one specific miss per output — fabricated detail, wrong audience assumption, voice drift, generic framing where your ICP language should be. "I liked this one better" is not discernment.
  • CRITIf both outputs are weak, send a third pass: "What's overconfident, missing, or generic in this output?" Ask AI to critique AI. Criticism beats consensus.
  • LOGLog the verdict. Your next session on this topic starts from your last approved output, not from scratch. Save winners as reference files.

Module 05 · Advanced Tier

Fix the Prompt.

Diagnose30 minAdvanced

When AI output fails, don't re-ask. Classify the break. Every failure falls into one of three modes. Name the mode, fix the mode.

The three failure modes

ModeSignalFix
Missing contextOutput is generic — says nothing specific to your system or projectAttach the source doc, paste the draft, include the raw notes. The model can't see what you see.
Vague instructionYou said "summarize," got a three-paragraph essay when you wanted five bullets with ownersRewrite instructions as a checklist. Count the bullets. Name the columns. Measure the output.
Model mismatchWrong tool — text model for video, general model for deep research, fast model for nuanced reasoningSwitch lanes. Perplexity for sourced research; a reasoning model for logic; a task agent for multi-step work.

Read the output like a stack trace

  • WHEREWhere did it drift? First sentence, middle, or conclusion? That localizes the break.
  • WHYWhy that drift? Missing a fact (context), ambiguous ask (instruction), or wrong tool (model).
  • LOGLog the fix. If you solved it today, the next person solves it in 90 seconds.
Fix in action

"Write acceptance criteria for the payment retry flow."

First run: generic AC that could belong to any retry flow anywhere. Diagnosis: missing context — the existing v2 AC was never attached. Fix: paste v2 AC, add constraint "align style to v2," re-run. Working spec on the second attempt.

Lab

Three broken prompts (see Lab Index). Diagnose the failure mode of each — context / instruction / model — and ship a fix. All three failure modes should be represented.

Success check

All three failure modes correctly classified and fixed prompts produce usable output without additional rounds.

Module 06 · Advanced Tier

Safe Output.
Human Landing.

Protect & Connect35 minAdvancedWarmth pass

Two things kill a creator's credibility fast: publishing output that doesn't sound like them, and shipping data or claims they can't stand behind. Safe output protects your reputation. Human landing earns the trust. You need both.

Creator guardrails — non-negotiable

  • VOICEDoes this sound like you? AI output defaults to polished and generic. If you'd be embarrassed to claim it in public, rewrite it. Your audience follows you, not the model.
  • VERIFYCan you stand behind every claim? AI will state things confidently that aren't true. Before you publish a statistic, a quote, or an attributed outcome — verify it. Your credibility is the product.
  • REVIEWNothing ships unread. Always do one full pass as your reader, not as the author. Read it cold. If you skim it, so will they.
  • EMPLOYERKeep your day job out of it. No employer names, no internal projects, no dollar amounts, no performance ratings. Disguise the specifics. The lesson is transferable; the data is not yours to share.

Warmth is a skill, not a vibe

AI writes efficiently. Humans respond to warmth. The gap between a good output and one that actually lands with an exec, a subscriber, or a hiring manager is almost always the warmth pass.

Exec update · before / after the warmth pass
Raw AI output
"Error rate 4.2%, up 0.9pp WoW. Two P1s open. Retry path on checkout implicated."
After warmth pass
"Refunds are slipping — 4.2% this week, nearly a full point up from last. Here's what we think caused it and the two levers we can pull by Friday."
  • STORYPair every number with the "why it matters" sentence. Data without narrative doesn't land. Executives and audiences both need context to act.
  • COACHAI as your tone coach. Write your draft terse and direct, then prompt: "Rewrite this with warmth — keep every number, add the human context, don't pad it."
  • SHIPSet a 10-minute timer. If you're still refining at 30 minutes, you've lost the plot. Diminishing returns kick in fast. Ship the 90% version.
Lab

Take something you need to communicate this week — a status update, a content intro, a reply to a subscriber question. Write the terse version yourself first (data only, no warmth). Then run it through the warmth pass prompt. Do one read-through as your reader. Time it — aim for under 10 minutes total. Ship it.

Success check

The final output passes your own "would I be proud to send this?" gut check. Every claim in it is something you can defend. It sounds like you — not a press release, not a report, not a chatbot.

Module 07 · Advanced Tier

Creative Unblocking.

Unstick yourself45 minAdvanced

Every operator hits a wall. The session stalls, the hook won't land, the credits run out, the integration doesn't exist. These seven moves are how you get through — each one grounded in the actual production pipeline behind From IT to Influence.

Move 1 — Prompt the prompter

  • The move: Stuck on what to write? Don't force it. Ask the AI what it needs from you first.
FITI pipeline example

Staring at a blank script, no hook landing. Instead of forcing it, prompt: "I'm writing a video for IT Directors who got passed over for promotion. What information do you need from me to write a hook that stops them mid-scroll?" Claude responds: I need the specific moment (the war story), the protagonist's wound, and what they discovered. Now you know exactly what to write first — and the hook writes itself from your answer.

Move 2 — Switch lanes, don't restart

  • The move: Export what you have and hand it to a different tool or skill. The work doesn't disappear — it migrates.
FITI pipeline example

Two sessions in, the script still isn't landing. Don't start over. Export the draft as markdown and invoke /video-script-review. The skill scores the draft across 7 dimensions — hook strength, ICP alignment, conflict clarity, resolution payoff. It tells you exactly which dimension is broken. You fix that one thing, not the whole draft. The switch took 3 minutes. Rewriting from scratch would have taken 90.

Move 3 — One answer, many formats

  • The move: One session can produce every asset you need. Don't re-run the pipeline — reformat the output.
FITI pipeline example

Script is approved. Same session, five prompts back to back: YouTube description with chapters. Thumbnail copy (ghost words + text overlay). Three Short hook briefs. Pinned comment template. Email teaser for the list. Total additional time: 14 minutes. Nothing regenerated — every prompt references the approved script in the same context window. One source of truth, five assets.

Move 4 — Constraint as fuel

  • The move: Running out of credits, time, or energy is a forcing function. Ship what you have instead of waiting to perfect it.
FITI pipeline example

11pm Friday. Claude usage limit hit. Script is 85% done — hook is solid, CTA is clear, the middle has two weak transitions. The rule: if the hook holds and the CTA closes, the middle can be tightened in edit. Ship the draft. Record Saturday morning. The constraint forced a decision that would have taken another two hours of refinement to reach the same place.

Move 5 — Checkpoint the artifacts

  • The move: Save each stage output as a file before moving to the next stage. Replayable, portable, recoverable.
FITI pipeline example

Every /fiti-production-run phase writes output to ~/Documents/YouTube-Videos/[slug]/production-run/ before the next phase starts. Week 2's video opens with the research note checkpoint from week 1 as the template — same format, same ICP framing, same structure. Claude reads it cold and picks up the context without being re-briefed. That's compounding. The checkpoint is what makes the second video faster than the first.

Move 6 — Build the bridge when no integration exists

  • The move: Any tool that exports data can feed AI. Extract → sanitize → prompt → use. Duct tape ships. Don't wait for the vendor.
FITI pipeline example

YouTube Analytics has no native Claude integration. The bridge: YouTube Studio → export CSV → strip the channel ID and email columns → prompt: "Summarize this week's performance. Surface the one video that outperformed and name what it did differently. Flag any retention cliff under 40%." Output pastes into the weekly brain update. No vendor required. Built in 20 minutes. Has run every Monday since.

Move 7 — Council / Devil's Advocate

  • The move: Before shipping anything consequential, open a second session and ask a different perspective to find what you missed.
FITI pipeline example

Script hook ready to record. Second Claude session opens with: "You are Marcus Chen — IT Director, 12 years in, strong performer, just got passed over for VP. You're scrolling YouTube at 10pm. I'm going to show you a video hook. Tell me honestly: do you stop scrolling or keep going? And if you stop, what made you stop?" Marcus is honest in ways self-review isn't. If he keeps scrolling, the hook doesn't ship. At least one council critique gets taken seriously — and you name the one you rejected and why.

Council review — what it actually produces

A named persona with a specific mood gives the AI a lens. "Skeptical reader who's out of patience" produces sharper critique than "review this critically" every time. Here's v1 → critique → v2 on a real content hook.

Council Review · Content Hook

Accurate. 10 words. Lands cold.

Devil's Advocate6 findings

  • "Content business" — where's the specific pain? Who is this for?
  • No conflict. Why would I stop scrolling?
  • No credibility signal — why should I trust this person?

Council prompt · named persona · copy this
ROLE: You are [a specific person with a specific mood and context].
You have [specific reason to be skeptical or pressed for time].
You read this in [specific situation — scrolling at 10pm, between meetings, etc.].
You do NOT soften your feedback.

TASK: Read the attached [hook / update / script section]. As this person, tell me:
  1. What will make you stop — or keep scrolling?
  2. What claim or phrase will you question or roll your eyes at?
  3. What reads like it was written by AI, not a person?
  4. One thing that would make you share this — or close the tab.

One finding per item. No encouragement. No rewrite.

Build your first skill — full walkthrough

Example: /weekly-exec-update — turn raw week notes into a polished leadership update in under 10 minutes. This is the most common repeating job for a Director-level operator. Build this one first.

Step 1 — Identify the repeating job
The test

Ask yourself: "Do I do this more than twice a week? Do I re-explain the format to AI every time? Does the output quality vary depending on how well I brief it?" If yes to any of these — it's a skill. The weekly exec update qualifies on all three.

Step 2 — Create the file
mkdir -p .claude/skills/weekly-exec-update
touch .claude/skills/weekly-exec-update/SKILL.md
Step 3 — Write the frontmatter
---
name: weekly-exec-update
description: Turn raw week notes into a polished executive status update in under
  10 minutes. Format: headline + accomplishments + blockers + next week commitments.
  Use when asked to write a weekly update, status report, or leadership summary.
---
Step 4 — Write the instructions
# Weekly Executive Update Skill

## What to do first
Say: "Paste your raw notes from this week — bullet points, half-sentences,
anything. I'll turn them into an executive update."

Wait for the paste. Do not generate anything until you have the raw notes.

## Output format

**This week's headline**
(One sentence. What moved? State the outcome, not the activity.)

**Accomplished**
- [past-tense verb] + [specific outcome] + [measurable impact if available]
- (3 bullets max — ruthless prioritization)

**Blockers** (only include if a decision or action is needed from above)
- [blocker] → [what you need, from whom, by when]

**Next week**
- [commitment] (verb-first, specific, not "continue working on")
- [commitment]

## Tone rules
- Exec-readable in 30 seconds cold
- Every bullet starts with a past-tense action verb: Shipped, Resolved,
  Closed, Presented, Launched, Reduced, Grew
- No jargon. No passive voice. No "I worked on" or "I was involved in."
- Warm but precise — write like a capable peer, not a status report template

## What to strip from the raw notes
- Activity without outcome ("Attended standup", "Reviewed PRs")
- Vague forward commitments ("Continue working on the migration")
- Internal project codes or acronyms your VP doesn't know
- Anything that makes you sound busy instead of effective
Step 5 — Test it
How to run your first test

Open Claude Code in your project. Type /weekly-exec-update. Paste a real week's raw notes when prompted. Read the output against your Module 2 Definition of Good for executive updates. If one bullet misses — add one rule to the SKILL.md that would have caught it. Re-run. That rule now applies to every future run forever. This is how skills compound.

Step 6 — Extend the skill over time
  • ADDAdd a "voice reference" block. Paste two examples of updates you've sent that landed well. The skill reads them before generating — output starts sounding exactly like you.
  • ADDAdd an audience block. Name your specific VP, their priorities, what they care about. The skill frames every update through that lens.
  • ADDWire it to a routine. Schedule the skill to prompt you every Friday at 4pm: "Paste this week's notes." You get a nudge, paste your notes, approve the output. Total time: 8 minutes.

Lab 01 — Prompt Brief template
Persona:        [the role AI should play — specific, not "expert"]
Context:        [paste the artifact, don't describe it — raw notes, draft, data]
Constraints:    [3 hard rules: tone, length, format, what to avoid]
Success metric: [one sentence — what "done" looks like, ideally measurable]
Non-goals:      [what NOT to produce — prevents scope creep]

Example filled:
Persona:        Senior ghostwriter who knows IT Directors at F500 companies
Context:        [pasted war story — 200 words, specific incident]
Constraints:    Hook under 30 words. No questions. Opens on a specific moment, not a feeling.
Success metric: An IT Director 10 years in stops scrolling within 3 seconds
Non-goals:      No listicle format. No "Here's what I learned."
Lab 03 — Production pipeline prompts (Stages 1–3)
STAGE 1 — Research note extraction
Persona: Content strategist who specializes in IT-to-executive career content
Context: [paste your war story — the specific incident, as raw as you have it]
Task: Extract the following — protagonist wound (what they wanted but didn't have),
      conflict moment (the specific scene), resolution (what changed), ICP hook
      (the one sentence that makes an IT Director say "that's me"), opening line
Output: One-page research note. Opening line at the top, bolded.

STAGE 2 — Script hook only (first 3 sentences)
Context: [paste Stage 1 research note]
Task: Write the first 3 sentences of the script. Sentence 1 opens on the wound
      — specific moment, not a feeling. Sentence 2 raises the stakes.
      Sentence 3 promises the resolution without delivering it yet.
Constraint: No questions. No "Have you ever." No "In this video."

STAGE 3 — Thumbnail brief
Context: [paste approved hook from Stage 2]
Task: Generate thumbnail copy. Format:
      Ghost words (2–3 words, large background text, the emotional trigger):
      Text overlay (5 words max, the promise):
      Expression direction (one word — the face the host makes):

Lab 07 — Council / Devil's Advocate prompt template
ROLE: You are [ICP name and profile — e.g., "Marcus Chen, IT Director, 12 years,
      just got passed over for VP promotion. You're skeptical and have seen
      every corporate influence playbook."]

TASK: I'm going to show you [a script hook / an exec update / a content brief].
      Read it as yourself — not as an editor, as the actual person this is for.
      Tell me:
      1. Do you stop scrolling (or read past the first line)? Yes or no.
      2. What made you stop — or what made you keep going?
      3. What's the one thing that would make this land harder?

Be honest. One finding per item. No encouragement.
